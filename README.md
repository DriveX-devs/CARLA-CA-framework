# CA — Cooperative Awareness with SiMO perception over a simulated V2X network

Experimental setup for **cooperative collision avoidance** between connected
vehicles (CAVs) and vulnerable road users (VRUs) at an urban intersection.
Four CAVs perceive the scene with **SiMO** (cooperative LiDAR + camera 3D
detection), share what they see with an **edge server over a simulated
vehicular network** (ns-3 with the DriveX modules: **5G NR Uu, IEEE 802.11p,
IEEE 802.11bd or the NR-V2X sidelink**), and the edge runs a **centralised
collision-avoidance algorithm** whose warnings travel back over the same
simulated network. Connected VRUs announce themselves with ETSI **VAMs**
generated by **DriveX's VRU Basic Service** inside ns-3. Every decision is
logged against CARLA ground truth.

This repository contains what is needed to **run the experiments and collect
their raw results**. Turning those results into figures and reports is a
separate concern and is not published here.

The pipeline compares cooperation policies under identical, replayable
traffic:

| policy | app mode | cell directory | what the collision avoidance sees |
|---|---|---|---|
| **On-board** | `1` | `policy_0_onboard` | each CAV decides alone, from its own perception |
| **Collaborative** | `2` | `policy_1_collaborative` | CAV detections uploaded to the edge; edge decides |
| **Collaborative + VAM** | `3` | `policy_2_vam` | as above, plus VRUs sending ETSI **VAMs** to the edge |
| **VAM-only** | `4` | `policy_3_vam_only` | edge fed **only** by VAMs and CAV ego states |

## 2. Setup from scratch

### 2.0. Prerequisites

Linux (tested on Ubuntu 24.04), an NVIDIA GPU with a working driver, `conda`,
`git`, `cmake`, `ninja`, a C++20 compiler, and enough free disk: CARLA 0.9.16
with the additional maps takes about 30 GB.

* `drivex-vbs-first-vam.diff` — restores the first VAM of the VRU Basic

  the run 100 ms after it starts.

## 3. Running experiments

### 3.1. A single run

```bash
./run.sh                                       # local CA only, 40 s, SiMO on LiDAR
./run.sh --seconds 20 --simo-cooperation ideal # cooperative SiMO (no network)
./run.sh --perception yolo --model m           # optional YOLOv8 backend: n | m | x
CARLA_RENDER=1 ./run.sh                        # with a CARLA window

./run_extended.sh --app-mode 2 --seconds 20    # + edge CA over 5G NR Uu
./run_extended.sh --app-mode 3                 # + VRU VAMs (DriveX VBS in ns-3)
./run_extended.sh --app-mode 4                 # VAM-only
ACCESS=11p   ./run_extended.sh --app-mode 3    # the same over IEEE 802.11p
ACCESS=11bd  ./run_extended.sh --app-mode 3    # IEEE 802.11bd
ACCESS=nrv2x ./run_extended.sh --app-mode 3    # NR-V2X sidelink (PC5 mode 2)
ACCESS=11p TOPOLOGY=hybrid ./run_extended.sh --app-mode 3
```

These launchers start CARLA if no server is listening, start a **fresh**
drivex-bridge when the mode needs one (its station mapping and clock epoch are
locked per run), execute the scenario and, unless `ANALYZE=0`, run
`analyze_ca_metrics.py` on the resulting run directory. `INJECTED_LOSS_PERC`
and `BRIDGE_RNG_RUN` add injected packet loss (`run_extended_pl.sh` is kept as
an alias).

Useful flags of `run_ca_extended.py` (forwarded through the launchers):
`--config`, `--town`, `--perception {simo,yolo,oracle}`, `--simo-sensors
{lidar,camera,both}`, `--simo-cooperation {none,ideal}`, `--simo-sweeps`,
`--simo-devices cuda:0,cuda:1`, `--model {n,m,x}` (YOLOv8), `--seconds`,
`--seed`, `--run-dir`, `--traffic-manifest` / `--create-traffic-manifest`,
`--save-stride` (`0` = no frames), `--no-ap`, `--warning-cooldown` /
`--no-warning-cooldown`, `--uplink-stagger-ms`, `--raw-only`, `--v2x-verbose`.

### 3.2. Perception: SiMO

SiMO is used through its split interface (`simo_perception.py`): every CAV
runs the **local stage** on its own sensors (optionally on its own GPU) and
produces a message; a **fusion stage** turns a receiver's own message, plus
any subset of the others', into boxes.

* `cooperation: none` (default) — each CAV detects from its own message only.
  This is what the four policies use: the tracker, the LDMs and the edge are
  fed exactly as they were with YOLOv8.
* `cooperation: ideal` — each CAV also fuses the messages of the CAVs within
  `comm_range_m`, handed over in-process: no network, no delay, no loss. The
  feature messages are **not** sent through ns-3 (uncompressed they are
  about 9.8 MB per CAV and frame).

The module also exposes what an edge-side scheme needs and the policies do
not use yet: a message for a station without sensors (`sensorless_message`,
i.e. fusion at the RSU), restricting a message to a set of BEV cells
(`SimoMessage.select_cells`), and its transmitted size.

**Sensors.** The SiMO rig (`simo.sensing`) reproduces the model's training
sensors: a roof LiDAR at 1.8 m keeping 32 rings between −30.67° and +9.69°
with 2048 points per ring, and (only when `sensors` uses them) six 1600×900
cameras with an 80° field of view. With the current prototype weights **run
LiDAR only**, as the SiMO package itself recommends.

**LiDAR sweeps.** The model was trained on up to 10 sweeps 0.43 s apart;
`simo.sweeps` selects how many are given. The default is **1**: on this
scenario a single sweep scored higher than 5 or 10 (see the table below),
and it is half the cost.

**Detection AP.** Every run scores its detections against CARLA ground truth
with the SimBEV2X rule the weights are reported with (centre distance, 0.5 /
1 / 2 / 4 m and their mean; `ap.json`, and the summary). Ground truth is
every actor within ±54.4 m of the CAV with at least one LiDAR return of the
current sweep, plus the parked cars and trucks of the map.

Measured on Town10HD_Opt (seed 11, 20 s, 4 CAVs, LiDAR only, 1 sweep,
prototype weights of 2026-11-11), pooled over the CAVs:

| class | AP 0.5 m | AP 1 m | AP 2 m | AP 4 m | mean | SimBEV2X test (package README) |
|---|---|---|---|---|---|---|
| car | 68.7 | 87.2 | 91.5 | 92.9 | **85.1** | 83.0 |
| bicycle (ridden) | 75.9 | 78.5 | 78.5 | 78.6 | **77.8** | 34.0 |
| pedestrian | 58.8 | 58.9 | 59.2 | 59.9 | **59.2** | 81.0 |

Pedestrians with five or more LiDAR returns are found 97 % of the time; the
AP is held down by the many far ones that count with a single return.

The same run with `--simo-cooperation ideal` (each CAV fusing the others'
messages), by CA category, mean AP:

| category | each CAV alone | ideal cooperation |
|---|---|---|
| vehicle | 84.7 | **88.3** |
| bike | 72.6 | **86.5** |
| pedestrian | 59.2 | **72.0** |

With 10 sweeps instead of 1 the single-agent figures drop to 80.0 / 63.7 /
51.2. The optional YOLOv8 backend is scored by category only, and only on
the detections above its confidence threshold: its AP is not comparable.

### 3.3. Network: access technology and topology

`ACCESS` selects the radio the bridge simulates; `TOPOLOGY` how the edge is
reached when that radio is not 5G:

| | CAV → edge | VRU VAM → edge | edge → CAV |
|---|---|---|---|
| `ACCESS=uu` | NR Uu | NR Uu | NR Uu |
| `TOPOLOGY=rsu` (default) | `ACCESS`, to an RSU at the gNB position | `ACCESS` | `ACCESS`, from the RSU |
| `TOPOLOGY=hybrid` | `ACCESS`, to the RSU | NR Uu | NR Uu |

In modes 3/4 the VRUs' VAMs are produced by **DriveX's VRU Basic Service
inside ns-3** (`--vbs`): the application only reports where each VRU is, the
service applies the ETSI TS 103 300-3 triggering conditions, encodes the VAM
and sends it through BTP and GeoNetworking; the edge's DriveX stack decodes
it. The GeoNetworking PDU travels as the payload of an ordinary bridge packet
(unicast to the edge, so on the 802.11 radios it is acknowledged and retried,
unlike a single-hop broadcast). GeoNetworking's own beacons travel too
(`gn_beacon` rows in `v2x_packets.csv`).

Things worth knowing about the radios (see the bridge's `DOCS.md` and its
validation report for the numbers):

* **NR-V2X mode 2 and simultaneous senders.** All CAVs upload at the same
  tick instant by default; stations that pick their own resources in the same
  slot collide (about 60 % delivered with eight 1 kB senders).
  `--uplink-stagger-ms` offsets CAV *i* by *i* × that many ms.
* **5G spatial channel.** With the bridge default `--channelUpdateMs=0` (kept
  for comparability with ns-3-v2x-bridge) a UE's channel is drawn once and
  does not follow it; an unlucky draw leaves one UE's uplink partly blocked
  for the whole run. `BRIDGE_EXTRA_ARGS="--channelUpdateMs=100"` updates it.

### 3.4. Other maps

`--town` (or `scenario.town`) takes any installed map: Town01–Town05,
Town10HD (each also as `*_Opt`), and with the AdditionalMaps package Town06,
Town07, Town11, Town12, Town13 and Town15. The CAV spawn points, the traffic
centre and the gNB / RSU position (`GNB_X`, `GNB_Y`) belong to the map: copy
`ca_convoy.yaml`, change them, and pass it with `--config`.
`scenarios/town06.yaml` is a worked example.

### 3.5. GPUs

* `CARLA_GPU=N` puts the CARLA server the launchers start on one GPU.
* `--simo-devices cuda:1,cuda:2` spreads the SiMO local stages over GPUs
  (CAV *i* on device *i* mod *n*).
* `CARLA_GPUS="0 1"` starts CARLA in its **multi-GPU mode**: a primary
  server that renders nothing and one rendering server per GPU, over which
  CARLA spreads the cameras. Two constraints of CARLA 0.9.16, both handled
  by the launcher: every server must be *started* on the scenario map (a map
  loaded from the client breaks the mode, so the run reuses the world:
  `--no-reload-world`), and **LiDAR returns on pedestrians are mostly lost**
  in this mode. Use it for camera-based perception, not for LiDAR-only SiMO
  (whose LiDAR is traced on the CPU anyway).

> **Pedestrians and the LiDAR.** In CARLA 0.9.16 a walker driven by the AI
> walker controller has its collision and physics switched off: the LiDAR
> gets no return from it and its velocity reads zero. The spawners switch
> both back on (`traffic_spawners.make_walkers_sensable`).

### 3.6. A campaign — `run_campaign.sh`

A *campaign* is a set of runs, one per random seed; each run collects one *cell*
per (policy × model), optionally repeated over a sweep of injected
packet-loss levels. Every cell of a seed replays the same traffic manifest, so
the policies are compared on byte-identical ground truth.

```bash
./run_campaign.sh                                     # 1 seed, 3 policies, SiMO
./run_campaign.sh --runs 10 --seconds 80              # 10 seeds × 3 cells
./run_campaign.sh --policies "1"                      # smallest useful campaign
./run_campaign.sh --access 11p --topology rsu          # over IEEE 802.11p
./run_campaign.sh --models "simo simo-coop"            # compare perception variants
./run_campaign.sh --policies "3" --loss "0 10 30 50 90" # packet-loss sweep
./run_campaign.sh --out output/mycampaign --attach --policies "4"
./run_campaign.sh --dry-run                           # print the commands only
```

| option | env | default | meaning |
|---|---|---|---|
| `--out DIR` | `OUT_DIR` | `output/campaign_<timestamp>` | campaign root |
| `--runs N` | `NUM_RUNS` | `1` | number of seeds |
| `--base-seed N` | `BASE_SEED` | `11` | run *k* uses seed `BASE_SEED + k - 1` |
| `--seconds N` | `RUN_DURATION_S` | `80` | duration of one cell |
| `--policies "1 2 3"` | `APP_MODES` | `1 2 3` | app modes to collect |
| `--models "simo"` | `MODELS` | `simo` | `simo`, `simo-coop`, `n` / `m` / `x` (YOLOv8), `oracle` |
| `--access A` / `--topology T` | `ACCESS` / `TOPOLOGY` | `uu` / `rsu` | radio and topology of the bridge |
| `--config PATH` | `CA_CONFIG` | the app default | scenario yaml |
| `--loss "0 10 50"` | `LOSS_PERCENTAGES` | none | injected packet loss [%]; cells nest under `loss_<pp>/` |
| `--save-stride N` | `SAVE_STRIDE` | `0` | annotated frames every N steps; `0` = none |
| `--attach` | `ATTACH` | `0` | add policies to the runs already in `--out`, replaying their seeds and manifests |
| `--no-smoke` | `SMOKE` | on | skip the 2 s sanity cell per policy |
| `--min-free-gb N` | `MIN_FREE_GB` | `60` | abort when free disk drops below this |
| `--max-attempts N` | `CELL_MAX_ATTEMPTS` | `3` | retries of a cell before giving up |

What it does for you:

* builds and **probes** the drivex-bridge before starting (a payload round-trip,
  plus a 100 %-loss probe when a loss sweep is requested), and skips ns-3
  entirely when only app mode 1 is collected;
* generates one **traffic manifest per seed** with a 2 s run, then replays it in
  every cell of that seed — across policies and across loss levels;
* is **resumable**: a cell holding `_SUCCESS` is re-validated, not re-run;
* **retries** a cell when CARLA segfaults, preserving the failed attempt under
  `<run>/_failed/`;
* runs a **disk watchdog** that aborts the campaign, and everything it spawned,
  before the filesystem fills up;
* validates every cell and every completed run with
  `validate_campaign_raw.py`;
* writes a `campaign.json` descriptor and a `batch.log` per campaign.

Campaign layout:

```
<out>/
├── batch.log
├── manifests/traffic_manifest_seed<S>.json    one traffic layout per seed
├── _manifest_smoke/seed<S>/mode_1             the 2 s run that created it
└── [loss_<pp>/]run_<k>_seed<S>/
    ├── campaign.json
    ├── _smoke/mode_<m>                        2 s sanity cell per policy
    └── <policy dir>/<model>/                  the cells
```

Always start a new setup with `--dry-run`, then with a single short cell
(`--policies "1" --seconds 4`), before committing to a long
campaign.

### 3.3. Disk

A cell writing annotated camera frames is ~2.9 GB, of which ~2.57 GB are the
frames; no metric reads them, which is why `--save-stride` defaults to `0`. At
that default a 10-seed × 9-cell campaign costs a few GB; with frames it costs
~250 GB. The disk watchdog (`--min-free-gb`, default 60 GiB) stops a campaign
before it fills the filesystem.

## 4. Collecting results

Everything a run produces goes under `output/` and is **gitignored**.

Per run directory (`output/run_<timestamp>/` or a campaign cell):

| file | written in | content |
|---|---|---|
| `metrics.csv` | always | one row per step, per CAV, per identified object: estimated position/speed/heading, matched GT actor (`gt_id`, `gt_name`, `gt_category`), errors, collision output (`t2c`, `s2c`, `ca_warning`, `ca_type`), edge-warning columns, and the per-step timing split (`t_detect_ms` = the CAV's local perception stage, `t_fuse_ms` = fusion + decoding, `t_track_ms`, `t_ca_ms`, `t_total_ms`) |
| `gt.csv` | always | ground truth of every dynamic object at every step |
| `gt_ca.csv` | always | the ground-truth collision decision for every (step, CAV, actor) pair: `distance_m`, `t2c`, `s2c`, `in_range`, `gt_ca_warning` — the reference every policy is scored against |
| `track_associations.csv` | always | which perception track was matched to which ground-truth actor, and at what distance |
| `stations.csv` | always | the ITS stations of the run (CAVs, VRUs) and whether they are connected |
| `timing.csv` | always | per-step perception timing |
| `run_metadata.json` | always | app mode, collision thresholds and the full resolved configuration of the run |
| `carla.log` | always | the CARLA server log of that run |
| `_SUCCESS` | on completion | marker used for resumability; its absence means the cell must be re-run |
| `edge_warnings.csv` | modes 2/3/4 | edge collision warnings with their end-to-end latency components |
| `v2x_packets.csv` | modes 2/3/4 | every simulated packet (uplink detections, VAMs, GeoNetworking beacons, downlink warnings) with its outcome, latency and the link it took |
| `bridge.log`, `bridge_send.csv`, `bridge_recv.csv` | modes 2/3/4 | ns-3 bridge logs |
| `VBS_stats.csv` | modes 3/4 | one row per VAM generated by a VRU Basic Service in ns-3 |
| `ap.json` | unless `--no-ap` | detection AP per CAV and pooled, per SiMO class and per CA category |
| `summary.txt` | without `--raw-only` | mean/RMSE errors, mean per-operation timing, detection AP, V2X statistics |
| `<Cav>/bev_<step>.png` | `--save-stride > 0` | bird's-eye frames (camera frames with the yolo backend) |

Two tools operate on these outputs:

```bash
# per-run metrics with 95 % confidence intervals: VRUs detected within a radius,
# misdetection probability (Wilson), and total warning latency (sensing +
# perception + uplink + edge CA + downlink + actuation)
python analyze_ca_metrics.py output/run_<timestamp> --vru-distance 40

# structural validation, no metrics: required files, headers, step counts, and
# identical ground-truth digests across the cells of a run
python validate_campaign_raw.py run <cell_dir> --app-mode 3 --steps 1600
python validate_campaign_raw.py campaign <run_dir> --steps 1600 \
    --policies 0,1,2 --models n,m,x
```

`run_campaign.sh` calls the validator itself, after every cell and at the end of
every run.

> **Analysis is out of scope here.** Producing figures, tables and reports from
> these CSVs is done outside this repository.

## 6. Troubleshooting

**The run hangs at start-up, or `time-out ... while waiting for the
simulator`.** A crashed run left the server in **synchronous mode with no
ticker**. Restart the CARLA server.

**`map ... is not installed on the CARLA server`.** The map of `--town` is not
in this CARLA installation: Town06, Town07, Town11, Town12, Town13 and Town15
come from the AdditionalMaps package.

**CARLA dies at boot with `Signal 11`.** Check the run's `carla.log`; relaunch
until the RPC port listens. `run_campaign.sh` retries a cell up to
`--max-attempts` times for exactly this reason.

**`waiting for the sensors to start...` that never ends.** In CARLA's
multi-GPU mode a rendering server is missing, or the world was reloaded from
a client. Start the servers through the launcher (`CARLA_GPUS=...`).

**No pedestrian is ever detected with the LiDAR.** Walkers spawned outside
`traffic_spawners.py` keep CARLA's default: no collision, hence no LiDAR
return ([§3.5](#35-gpus)). The same happens in multi-GPU mode.

**`ERROR: UDP port 5555 is already in use`.** A bridge must be started fresh for
every run. Stop the previous one:
`echo '{"msg_type":"shutdown"}' | nc -u -w1 127.0.0.1 5555`.

**`no up-to-date drivex-bridge binary`.** `NS3_BRIDGE_DIR` does not match the
bridge's directory, or the ns-3 build failed. Re-run `./setup_env.sh`.

**The bridge aborts with `checkVamConditions() was called before sending any
VAM`.** The DriveX-sim checkout lacks `drivex-vbs-first-vam.diff`
([§2.4](#24-ns-348--drivex--drivex-bridge--skip-for-app-mode-1)).

**Unmatched perception tracks in `metrics.csv`.** Town10HD_Opt contains parked
vehicles that are map meshes, not CARLA actors: they are correctly detected
but have no actor ground truth (the detection AP does count them). Not a bug.
